# SaySo Training Pipeline

Reproducible fine-tuning pipeline for SaySo's Home Assistant native tool-calling
conversation agent. Base model: `google/functiongemma-270m-it` with Home-LLM's
FunctionGemma chat template (see `configs/functiongemma-270m.yml`).

## Upstream

Home-LLM is pinned in `upstream.lock.json` (currently `develop` @
`50cf35c9b66440f64ce45baeb3f5b39a2f382cd1`). Pin locally:

```bash
python training/scripts/pin_upstream.py
```

## Quick start

```bash
python -m venv training/.venv
source training/.venv/bin/activate
pip install -r training/requirements.txt
pip install pyyaml  # config validation tests
python -m pytest training/tests -q
```

## Dataset views

The adapter produces two JSONL views from the same converted examples:

- **sayso** (`--view sayso`): OpenAI-compatible `function.arguments` remain JSON
  strings for SaySo runtime / payload compatibility.
- **axolotl** (`--view axolotl`, default): argument strings are parsed to dicts
  so the FunctionGemma jinja template renders native `key:value` call syntax.
  Each message carries `train_on_turn`: `true` only on assistant tool-call and
  final TTS turns; system, user, and tool turns are `false`.

Smoke training reads `fixtures/sayso_axolotl_smoke.jsonl`. Production eval uses
`test_datasets` → `datasets/sayso_val.jsonl` (generated by split).

## Pipeline commands

| Step | Command |
|------|---------|
| Pin upstream | `python training/scripts/pin_upstream.py` |
| Generate + adapt | `python training/scripts/generate_dataset.py --language english --size small` |
| Adapt only | `python training/scripts/adapt_dataset.py INPUT.jsonl OUTPUT.jsonl --seed 42` |
| Split 80/10/10 | `python training/scripts/split_dataset.py INPUT.jsonl --out-dir training/datasets` |
| Detect GPU | `python training/scripts/detect_gpu.py` |
| Smoke train | `python training/scripts/train.py --config smoke` |
| Production train | `python training/scripts/train.py --config prod` |
| Evaluate | `python training/scripts/evaluate.py training/evals/adversarial.jsonl` |
| Export GGUF | `python training/scripts/export_gguf.py --checkpoint PATH --dry-run` |
| Verify llama.cpp | `python training/scripts/verify_llamacpp.py --dry-run` |

## Dataset composition target

- 65% core single-action controls
- 15% multiple actions/targets
- 10% failures/unsupported/ambiguity/refusals
- 5% status questions
- 5% no-tool conversational

English-only for the first run. Legacy service-call formats and unsupported tools
are rejected by the adapter with counted reasons.

## GPU notes (GTX 1070 / Pascal)

Smoke and production configs use **FP16**, **no BF16**, and **no flash-attn**.
Run `python training/scripts/detect_gpu.py` before training. If no GPU is present,
`train.py` exits 0 with a documented skip message.

## Quality gates (initial targets)

| Metric | Target |
|--------|--------|
| Protocol valid tool calls | ≥99% |
| Single-action tool name | ≥95% |
| Schema-valid arguments | ≥98% |
| No-tool decision | ≥95% |
| Multi-action exact match | ≥90% |
| Unsupported tool hallucination | <1% |

Measured failures are preserved in `artifacts/eval_results.json`; gates are not
fabricated in unit tests.

## Layout

```
training/
  adapters/          Home-LLM V2 → SaySo JSONL adapter
  artifacts/         Checkpoints, eval outputs (gitignored)
  configs/           Axolotl YAML (smoke, prod, base)
  datasets/          Generated JSONL (gitignored)
  evals/             Metrics, harness, adversarial set
  fixtures/          Small test fixtures (committed)
  scripts/           Documented pipeline operations
  tests/             Unit tests (no model downloads)
  upstream.lock.json Pinned Home-LLM commit
```

## Adversarial eval

`evals/adversarial.jsonl` is held out from training and hyperparameter selection.
